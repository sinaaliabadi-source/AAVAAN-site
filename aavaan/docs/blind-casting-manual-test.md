# تست دستی کستینگ ناشناس (Blind Casting)

هدف: اطمینان از اینکه نام واقعی و اطلاعات تماس هنرمند در **بخش کستینگ عمومی**
(پروفایل عمومی و جستجوی تیم تولید) فقط پس از خرید/مصرف دسترسی و ثبت رکورد
`ProductionAccessLog` نمایش داده می‌شوند، و این مخفی‌سازی **سمت سرور** است — یعنی
اطلاعات واقعی اصلاً وارد HTML پاسخ نمی‌شود، نه اینکه صرفاً با CSS پنهان شود.

> این قانون فقط شامل کستینگ عمومی (`ArtistProfile` / `ProductionAccessLog`) است.
> بخش‌های `honarbaz` و پنل ادمین از این قانون مستثنا هستند و همیشه نام واقعی را می‌بینند.

## شناسهٔ مستعار
پیش از باز شدن دسترسی، به‌جای نام واقعی، شناسهٔ پایدار **«هنرمند #<id>»** نمایش داده می‌شود
(`$profile->id` / `$artist->id`). این انتخاب چون پایدار و بدون افشای هویت است استفاده شد.

## داده‌های آزمایشی
1. یک کاربر هنرمند بسازید (role = `artist`) با نام واقعی مشخص، مثلاً «علی رضایی واقعی»،
   و یک `ArtistProfile` فعال (`is_active = true`) با `phone_contact` و `email_contact`.
2. یک کاربر تیم تولید بسازید (role = `production`).

## سناریوها

### ۱) کاربر مهمان (بدون ورود) — پروفایل عمومی
- برو به `‎/profile/{username}`.
- **انتظار:** در صفحه «هنرمند #<id>» دیده شود؛ نام واقعی، شماره و ایمیل دیده نشوند.
- **بررسی سمت سرور:** سورس HTML صفحه را باز کن (Ctrl+U) یا:
  ```
  curl -s https://<host>/profile/<username> | grep "علی رضایی واقعی"
  ```
  باید **هیچ نتیجه‌ای** برنگرداند. همچنین شماره و ایمیل نباید در سورس باشند.

### ۲) کاربر تیم تولید بدون دسترسی — پروفایل عمومی
- با کاربر production وارد شو (بدون هیچ `ProductionAccessLog` برای این پروفایل).
- برو به `‎/profile/{username}`.
- **انتظار:** «هنرمند #<id>» + کارت CTA «اطلاعات تماس هنرمند 🔒».
- **بررسی سمت سرور:** در سورس HTML نباید نام/شماره/ایمیل واقعی باشد.
  رشته/شهر/سن/عکس/بیوگرافی/نمونه‌کار/سوابق کاری باید دیده شوند.

### ۳) کاربر تیم تولید با دسترسی — پروفایل عمومی
- برای این پروفایل یک `ProductionAccessLog` بساز
  (`production_user_id` = کاربر production، `artist_profile_id` = این پروفایل)،
  یا از دکمهٔ «🔓 مشاهده اطلاعات تماس» استفاده کن (نیازمند اعتبار پرداخت‌شده).
- صفحه را دوباره باز کن.
- **انتظار:** نام واقعی + شماره + ایمیل در سورس HTML دیده شوند.

### ۴) خودِ هنرمند — پروفایل خودش
- با کاربر هنرمند وارد شو و پروفایل خودش را باز کن.
- **انتظار:** همیشه نام واقعی و اطلاعات تماس خودش را می‌بیند.

### ۵) جستجوی تیم تولید (`/dashboard/production/search`)
- بدون دسترسی پولی: کارت‌ها «هنرمند #<id>» را نشان می‌دهند (نه نام واقعی).
- با دسترسی پولی ولی پیش از باز کردنِ یک هنرمند خاص (`$unlocked = false`): همچنان
  «هنرمند #<id>».
- پس از باز کردن آن هنرمند (`$unlocked = true`): نام واقعی نمایش داده می‌شود.
- **بررسی سمت سرور:** در سورس HTML صفحهٔ جستجو، نام هنرمندانِ باز نشده نباید موجود باشد.
- جستجوی کلیدواژه فقط روی **بیوگرافی** کار می‌کند و دیگر روی نام هنرمند جستجو نمی‌کند
  (تا هویت از طریق نام قابل حدس/تأیید نباشد).

### ۶) اعتبارسنجی بیوگرافی
- در داشبورد هنرمند → ویرایش پروفایل، در فیلد بیوگرافی یک شماره موبایل
  (مثلاً `09121234567` یا با ارقام فارسی `۰۹۱۲۱۲۳۴۵۶۷`) یا یک ایمیل وارد کن و ذخیره کن.
- **انتظار:** خطای اعتبارسنجی؛ ذخیره نشود. (تشخیص: هر رشتهٔ ۸ رقم یا بیشتر، یا الگوی ایمیل.)

## تست خودکار
فایل `tests/Feature/BlindCastingTest.php` همین رفتار را با `assertStringNotContainsString`
روی بدنهٔ HTML پاسخ بررسی می‌کند (اثبات مخفی‌سازی سمت سرور). اجرا:
```
php artisan test --filter=BlindCastingTest
```
